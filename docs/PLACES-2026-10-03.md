# 跨 place 對局：大廳與獨立對戰伺服器

每場對局不再和大廳、其他房間共用同一台伺服器。大廳 place 只負責集合與房間設定；滿員且全員準備後，伺服器預留一台對戰 place 的獨立保留伺服器，把整隊傳送過去。每台對戰伺服器只執行一場戰局，四個匹配點可以同時出發。

## 角色判定

同一份 build 發布到同一體驗內的兩個 place，伺服器依 `game.PlaceId` 與 `GameConfig.Places` 決定角色（`ServerModules/PlaceRules.lua`）：

| 角色 | 條件 | 行為 |
| --- | --- | --- |
| `Lobby` | `PlaceId == lobbyPlaceId` | 城堡廣場、房間設定、準備；出發時預留對戰伺服器並傳送，不生成戰場。全域階段維持 `Lobby`，各房間各自顯示「隊伍正在出發」。 |
| `Match` | `PlaceId == matchPlaceId` | 不建立廣場；讀取票據、等待名單抵達後開局。結束後玩家可按「返回大廳」，`returnDelay` 秒後自動送回。 |
| `Combined` | Studio、ID 未設定（預設 0）、兩者相同或未知 place | 與先前相同的單一伺服器流程。 |

客戶端讀 `workspace.PlaceRole` 調整出發畫面與結算按鈕。

## 安全設計

- 對局設定與名單由大廳伺服器寫入 MemoryStore HashMap `RTSMatchTickets_v1`，鍵為 `ReserveServer` 回傳的 PrivateServerId，TTL 為 `ticketTtl`。對戰伺服器只讀自己 `game.PrivateServerId` 的票據，且必須是無擁有者的保留伺服器。
- `TeleportData` 只放對局識別，不用於任何判斷；客戶端能竄改它。
- 對戰伺服器以 `PlaceRules.readTicket` 重新驗證版本、時效、房間、名單（1–4 名、正整數且不重複的 UserId）與設定（再走 `LobbyRules.settings`）；任一欄位不符就整張拒絕並送回大廳。
- 名單外、或開局後才抵達的玩家送回大廳。文明取自票據，經 `CivilizationRules.resolve` 回到合法值。

## 失敗處理

- 預留、寫入票據或傳送任一步失敗（各重試 `teleportAttempts` 次）：刪除票據，房間解鎖，全員取消準備並收到提示；不扣任何資源。
- 傳送送出後才失敗（`TeleportInitFailed`）：`Flooded`／`Failure` 只重送該玩家；耗盡次數、或其他結果（滿員、未授權）則恢復該玩家的房間狀態。
- 大廳等待超過 `travelTimeout` 仍未離開伺服器的成員視為失敗並恢復。
- 對戰伺服器等待 `arrivalTimeout`：全員到齊立即開局；逾時以已抵達者開局（設定對該人數無效時送回大廳）；沒有人抵達則不開局，空伺服器由 Roblox 關閉。
- 對戰伺服器關閉時（`BindToClose`）盡量把仍在場的玩家送回大廳；返回失敗會提示再按一次。

## 上線設定步驟（需由使用者在 Creator Hub 操作，本輪未執行）

1. 在同一體驗內新增第二個 place 作為對戰 place；原起始 place 作為大廳。
2. 把兩個 place ID 填入 `src/ReplicatedStorage/GameData/GameConfig.lua` 的 `Config.Places.lobbyPlaceId`／`matchPlaceId`。
3. 用 `.\rojo.exe build default.project.json -o build/AOE2.rbxlx` 產生 build，分別發布到兩個 place。兩邊必須是同一版本，否則票據或設定欄位可能不相容。
4. 同體驗內的 place 傳送不需額外開啟第三方傳送；MemoryStore 不需設定。若發布伺服器輸出 `[RTS Travel]` 警告，依訊息檢查。

## Studio 模擬

Studio 無法傳送，預設一律是 `Combined`。`place-split-match-validation.project.json` 在 ServerScriptService 設定 `RTSPlaceRole="Match"` 與 `RTSStudioSettings`（1 名真人＋1 簡單電腦、小地圖），可在 Play 中檢查對戰伺服器流程：出發畫面 → 自動開局 → 結算顯示「返回大廳」。Studio 的返回大廳傳送會失敗並顯示提示，屬預期行為。`RTSStudioTutorial=true` 可模擬新手教程局。Server & Clients 或命令列 `numTestServerPlayers` 的測試玩家 UserId 為負數（Player1=-1）；只有伺服器判定為 Studio 時才接受負數 ID，正式伺服器與票據內容都不能放寬這項檢查。

- CLI：`scripts/verify.ps1` 全部通過，含新增 `tests/place_travel.spec.lua` 116 項（角色、票據竄改／過期、劇情章節與新手教程票據、Studio 測試玩家負數 UserId、抵達、傳送重試與失敗恢復，引擎服務以替身代替），以及原有 65 項大廳房間流程（確認單一伺服器模式不變）、Luau `-O0` 區域變數上限與 Rojo build。
- **未驗證**：Studio Play 的對戰 place 模擬、實際發布後的 ReserveServer／MemoryStore／TeleportAsync、多房間同時出發、傳送失敗恢復、返回大廳與空伺服器關閉。這些必須在已發布的測試體驗以真實帳號驗收，不能以 CLI 結果代替。
