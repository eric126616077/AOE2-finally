# 王國商店：金冠、外觀與 Robux 商品（不付費取勝）

本輪加入讓玩家願意花 Robux 的元素，但所有付費內容只改變外觀或大廳展示，不影響對戰。這仍是原型；Robux 商品與通行證還沒有在 Creator Hub 建立，所以正式環境的購買按鈕會顯示「尚未上架」。

## 公平原則（程式強制）

- 不賣資源、加速、人口、生命、攻擊、科技或任何對戰數值。`ShopRules.audit` 以白名單檢查每個商品、外觀、禮包、通行證與成就的欄位；出現其他欄位（例如 `damage`、`food`、`populationBonus`）時伺服器拒絕啟動。
- 沒有隨機抽獎：每個商品都標明內容與價格。
- 外觀只換**非隊伍色**零件的顏色與材質，不改大小、透明度、碰撞或選取範圍，所以敵我辨識和預設外觀相同。
- 金冠只能買外觀，也可以免費取得。王室通行證的「每日登入 +50%」只多給金冠，不影響對戰。
- 對戰中外觀固定：開局後不能更換，商店入口隱藏。

## 免費取得金冠

數值在 `GameData/ShopCatalog.lua` 的 `rewards` 與 `milestones`：

- 每日登入：連續第 1–7 天 20／25／30／40／50／60／120，之後循環；中斷一天從第 1 天開始。以臺灣時間午夜重置。
- 完成對局（劇情、對戰、合作）：25；勝利 +25；玩家對戰勝利再 +15；每日首勝 +50。對局少於 5 分鐘、投降或練習局沒有獎勵。每天從對局取得的金冠上限 300（首勝獎勵另計）。
- 一次性成就：完成或關閉教程 100；劇情第 1–4 章各 60；劇情全破 150＋「河谷英雄」稱號＋「史詩城塞」風格；10 場對戰勝利 100＋「常勝將軍」稱號＋「百戰鏽甲」。已經達成的舊玩家，下次進遊戲時會補發。

### 上架步驟（由使用者操作，本輪未執行）

1. 在 Creator Hub 該體驗的「Monetization → Developer Products」建立上面 5 個開發者商品；「Passes」建立王室通行證。
2. 把產生的 ID 填入 `src/ReplicatedStorage/GameData/ShopCatalog.lua`：`products[*].productId` 與 `passes.vip.gamePassId`。0 代表未上架，按鈕會停用。
3. 確認體驗已開啟 API Services（DataStore），然後用 `.\rojo.exe build default.project.json -o build/AOE2.rbxlx` 建置，大廳與對戰 place 都要發布同一版本（任一台伺服器都可能處理收據）。
4. 在 Studio 用測試購買確認一次（Studio 購買不收費）。

## 伺服器與資料

- `GameData/ShopCatalog.lua`：商品資料。`Shared/ShopRules.lua`：稽核、擁有／裝備解析、每日與對局獎勵計算（客戶端與伺服器共用的純規則）。
- `ServerModules/WalletRules.lua`：錢包資料驗證與交易（`receipt`／`grant`／`milestone`／`daily`／`buy`／`equip`）。不認得或損壞的資料整份拒絕，伺服器不會覆寫。
- `ServerModules/WalletStore.lua`：獨立的 DataStore `RTS_Wallet_v1`（不改動原有個人檔案）。每次異動都是一次 `UpdateAsync`，在轉換函式裡用雲端目前資料重算，所以多台伺服器同時寫入也不會重複發放或透支；寫入失敗不扣款、不發放。裝備選擇延遲 4 秒合併寫入，離開時立即寫入。Studio 或未發布的 place 使用本次遊玩的記憶體錢包。
- `ServerModules/Shop.lua`：唯一的 `MarketplaceService.ProcessReceipt`。收據寫入成功或之前已寫入，才回報 `PurchaseGranted`；其他情況回 `NotProcessedYet`，Roblox 會稍後重送。收據編號記在錢包裡（最近 256 筆）避免重複發放。通行證以 `UserOwnsGamePassAsync` 檢查。
- `Shared/CosmeticArt.lua`：依共用色票把顏色換成外觀配色；加上大廳稱號、拖尾與勝利特效。
- 主腳本只加了幾個掛鉤（`GameServer` 的區域變數已達 200 上限，所以用 `Shop.Get()` 單例）：加入／離開、`Shop` 指令、建築生成套用風格、對局結束發獎勵與施放勝利慶典。單位塗裝在 `ModelFactory.unit` 套用。
- 客戶端只送 `Command("Shop", 子指令, 參數)`：`Buy`、`Equip`、`ClaimDaily`、`PromptProduct`、`PromptPass`。伺服器以屬性同步 `Crowns`、`OwnedCosmetics`、`Cosmetic*`、`ShopVIP`、`Daily*`、`WalletStatus`。購買／領取同時只處理一筆，連點不會重複扣款。
- Studio 測試用屬性（只在 Studio 生效）：ServerScriptService 的 `RTSTestCrowns`（記憶體錢包起始金冠）、`RTSTestVIP`（視為擁有通行證）。
