# 帝國鍛造坊：Roblox RTS 測試版

受《帝國時代 II》啟發的桌面 RTS，使用 Luau 與 Rojo 7.6.1。這次擴充已包含可設定的對局、AI 經濟與軍隊、四個時代、施工、交貨、科技與勝負規則；仍是需要 Roblox Studio 驗收與持續完善的測試版，不是 100% 複製或完整《帝國時代 II》。玩家介面與提示使用繁體中文。

## 開始對局

進入 Play 後由房主在大廳設定戰局，按「開始戰局」。每方從一座已完成的市鎮中心、三名村民與一名斥候騎兵開始。人數不足可加入電腦，也可選「自動補滿」；人類玩家與 AI 合計最多四方。開局後加入的玩家觀戰，下一局再參加。

| 設定 | 選項與規則 |
| --- | --- |
| 地圖 | 小型 768、標準 1024、大型 1536 studs；預設標準。格線為 8 studs。 |
| 電腦 | 0–3 方或自動補滿空位；0 AI 且只有一名玩家時為沙盒練習。 |
| AI 難度 | 簡單、普通、困難；影響經濟規模、軍隊規模與進攻頻率。 |
| 每方人口上限 | 60、100、150、200；仍須建造房屋取得實際人口容量。 |
| 初始資源 | 標準：食物 300、木材 300、黃金 150、石材 150。豐富：食物／木材各 1200、黃金 800、石材 600。 |
| 勝利規則 | 征服、主城決戰、奇觀。 |

地圖以固定種子生成，四個出生地有對稱的資源配置、基地空間與通往中央的道路。三種尺寸分別以約 420／680／1100 個資源點為生成目標；可用位置與間距會影響實際數量。樹林、金礦、石礦與漿果叢分成資源群，基地周圍保留 128 studs 的起始建設區。完整複製使用 `Workspace.StreamingEnabled=false`，RTS 不依賴玩家角色作為串流中心。

## 經濟、建造與發展

村民採集後先攜帶資源，交到自己的合適建築才加入餘額。市鎮中心、城堡與市集可收四種資源；磨坊收食物，伐木場收木材，採礦營地收黃金與石材。農田可提供食物，採集點耗盡後需要尋找其他資源；農田耗盡保留建築。經濟科技會增加採集效率、攜帶量或農田容量。

建築必須在地圖內、占地無障礙、有村民在 80 studs 內、達到所需時代且資源足夠。提出建造後須由村民施工，並非立即完成；可選更多村民右鍵施工中的建築以協助。右鍵自己的受損建築可修復，修復消耗木材。人口由已完成建築提供，房屋增加 5 人口；每棟生產建築可排五個單位，佇列預留人口。出口被堵住時等待空位，不強行把單位生進障礙。

共 18 種建築：市鎮中心、房屋、磨坊、伐木場、採礦營地、兵營、農田、射箭場、馬廄、兵工廠、市集、瞭望塔、石牆、城堡、攻城器械廠、修道院、大學、世界奇觀。修道院目前是可建造的時代建築，僧侶與招降尚未實作。增建市鎮中心需城堡時代；城堡需 650 石材。

| 升級 | 成本 | 前置條件 |
| --- | --- | --- |
| 黑暗 → 封建 | 500 食物 | 完成兩種不同的黑暗時代經濟／軍事建築，例如兵營、磨坊、伐木場、採礦營地。 |
| 封建 → 城堡 | 800 食物、200 黃金 | 完成兩種不同的封建時代經濟／軍事建築，例如射箭場、馬廄、兵工廠、市集。 |
| 城堡 → 帝王 | 1000 食物、800 黃金 | 完成一座城堡，或兩種不同的城堡時代建築，例如攻城器械廠、修道院、大學。 |

房屋、農田、城牆、瞭望塔與市鎮中心不列入上述兩種建築計數。同一種建築蓋兩座仍只算一種。選自己的市鎮中心後按「升級時代」或 U；生產與研究共用建築，需要先清空其佇列。

共 11 項科技：織布機、手推車、雙刃斧、馬軛、重犁、鍛造、鎖甲、箭羽、拇指環、化學、徵兵制度。科技在對應建築研究，需符合時代與資源條件；重犁需先研究馬軛。織布機改善村民生命與護甲，手推車提升村民效率，軍事科技改變適用部隊的攻擊、護甲、射程與攻擊間隔。

市集可每次買入或賣出 100 食物、木材或石材：買入花 130 黃金，賣出獲得 70 黃金。目前採固定交換價格。

## 軍隊與勝利

共 10 種單位：村民、步兵、長槍兵、弓箭手、斥候騎兵、矛兵、騎士、攻城衝車、投石車、巨型投石機。兵營、射箭場、馬廄、攻城器械廠與城堡負責各類生產，後期單位依時代解鎖。

軍隊會自動索敵與反擊；瞭望塔及城堡會自動射擊。長槍兵克制騎兵，矛兵克制弓箭手，騎士適合突襲遠程部隊，攻城衝車與巨型投石機有對建築加成；投石車可造成範圍傷害。傷害、護甲、資源、所有權與移動由伺服器決定，客戶端的步行、採集、攻擊與介面動畫只負責顯示。

- **征服**：摧毀對方全部單位與建築才消滅該陣營，包括房屋、農田及城牆；最後存活的陣營獲勝。
- **主城決戰**：保護開局那座市鎮中心。起始主城被摧毀立即戰敗，後來增建的市鎮中心不替代勝敗目標。
- **奇觀**：完工的世界奇觀須存活 180 秒才獲勝；消滅所有其他陣營也可獲勝。
- 玩家投降或離開會清除其單位與建築。沒有對手的征服／主城決戰沙盒不自動宣布勝利；投降後可回大廳。單人奇觀局仍可達成奇觀勝利。
- 對局結束可觀戰結果，由房主返回大廳調整設定並重開，無須重新啟動 Play。

## 操作

| 操作 | 功能 |
| --- | --- |
| WASD／方向鍵、Shift | 移動相機；Shift 加速。 |
| 滾輪、Home、小地圖 | 縮放、回基地、移動視角。 |
| 左鍵、左鍵拖曳 | 選取、框選自己的單位。 |
| Shift + 左鍵、雙擊單位 | 加選／取消單選、選取畫面內同類型單位。 |
| 右鍵地面／資源／敵人 | 移動／採集／攻擊。 |
| 村民右鍵自己的建築 | 協助施工、修復，或交回攜帶的資源。 |
| B、R | 切換建造頁、研究頁；建築用介面卡片選擇。 |
| 建築預覽時左鍵、Shift + 左鍵 | 建造一次、保留預覽以連續放置。 |
| 右鍵／Esc | 取消建築預覽。 |
| T、U、X | 在選取建築訓練預設單位、升級時代、停止所選單位。 |
| V、H、句點 `.` | 選全部自己的村民、選市鎮中心、循環選取閒置村民。 |
| Ctrl + 1–9、1–9、快速連按同一數字 | 儲存編隊、選取編隊、把相機移到編隊。 |

右上「動態」可減少介面與單位的視覺動態；「選單」可開啟邊緣捲動。HUD 有資源、人口、時代、陣營資訊、選取單位資料、建造／訓練／研究、佇列、小地圖與戰局選單。輸入命中與相機座標考慮 GuiInset，HUD 使用 UIScale 適應視窗。

## 連接 Studio、模型與備份

在專案目錄執行 `./scripts/serve.ps1`，或：

```powershell
.\rojo.exe serve default.project.json --address 127.0.0.1 --port 34872
```

在 Studio Rojo 7.6.1 插件按 Connect，使用 `localhost:34872`。服務須持續執行才能同步；若埠已占用先檢查現有服務。`rojo build` 只輸出檔案，不啟動同步。Play 中更新了腳本後，停止並開新 Play 才能驗證初始化。

既有 `ReplicatedStorage/Buildings`、`Resource` 模板會優先使用；缺少模型時使用 `Shared/Art.lua` 的原創幾何外觀，並非官方 AOE2 美術。複製品內的舊腳本會移除，原模板保留。`Workspace` 與 `ReplicatedStorage` 的未知實例不被 Rojo 刪除；地圖重建只清除有本系統標記的資源與裝飾，不刪除使用者的未知模型。

本輪修改前的程式備份在 `C:\Users\user\AppData\Local\Temp\AOE2-before-20260930-142522`，原 Studio place 備份在 `build/Original-before-20260930.rbxl`。更早的遷移備份為 `C:\Users\user\AppData\Local\Temp\AOE2-before-20260929-225511`。輸出到 `build`；不自動發布 Roblox 體驗，不覆蓋原 place。無副檔名 `*Setup` 與舊模組保留為遷移參考，不啟用第二套生成流程。

## 驗證與未完成範圍

```powershell
.\scripts\verify.ps1
```

驗證會編譯 Luau，執行核心、對局設定與種子地圖測試，最後執行：

```powershell
.\rojo.exe build default.project.json -o build/AOE2.rbxlx
```

目前 CLI 驗證已通過 205,531 項格線／有限數值／原子扣款檢查、136 項對局／經濟／設定／單位冷卻與人口容量檢查、13,667 項地圖／資源公平性／未知實例保留檢查，並通過語法編譯與 Rojo 建置。Studio Play 已取得 [35 項基礎檢查紀錄](tests/latest-studio-results.txt)；當時 AI 人口至少 4 人的條件可由起始單位滿足，不能證明新增村民。新版已改為核對 Workspace 中該 AI 的實際村民實例數超過起始數量，這項嚴格斷言尚未重跑。真正雙人客戶端另外取得 [29 個 PASS](tests/latest-multiplayer-results.txt)，涵蓋跨端建築／訓練、所有權、實際退出清理、勝利與房主轉移。大型 1536 地圖 Auto 補三個 AI 的手動操作已觀察採集、建造、訓練、小地圖及 AI 軍隊出現，但尚非完整長局或效能驗收。CLI 或局部實機通過不能代表所有遊戲規則通過。

上述通過紀錄之後另有單位動畫晚到部件追蹤、未知障礙的建造預覽、伺服器指令冷卻與人口容量處理修正，以及進階測試複製等待與農田容量斷言修正。這些最後變更未完成整體 Studio 重跑，35／29 項紀錄只支持當時的測試版本與範圍，不能宣稱最新整體建置全部通過。

本輪 Studio 驗收狀態與操作見 [tests/STUDIO.md](tests/STUDIO.md)。請在新的 Play 工作階段、客戶端 Command Bar 執行：

```lua
task.spawn(function()
    require(game.ReplicatedStorage.Shared.StudioTests).Run()
end)
```

這個測試會改變測試局的資源、建築與單位，每個新 Play 工作階段執行一次。Command Bar 的 ModuleScript 快取與遊戲腳本分離，HUD 驗收需讀取實際 PlayerGui。雙人重現方法使用 `Shared/MultiplayerTests`，見驗收文件；已驗證的退出與同步範圍之外，AI 長局、完整軍事對抗、三種實際勝利條件、所有科技／建築／單位及不同視窗尺寸仍待確認。

單人回到大廳後可另執行 `Shared/ProgressionTests.Run()`，檢查不同建築前置、織布機、封建時代、市集交換與軍事／經濟科技。只在明確呼叫時開始小地圖、豐富資源、無 AI 的測試局，最多執行五分鐘。首次執行因起始設定複製尚未完成而失敗，條件等待已修正且編譯通過；後續原生輸入工具無法啟用 Studio 視窗，未取得完整重跑結果，**進階測試尚未通過驗收**。完整時代、科技、奇觀、全部建築與效能仍保持未驗證。

尚未實作或尚待完善：文明差異與完整科技樹、戰役、海軍、戰爭迷霧、僧侶招降與聖物、羊群／野豬等畜牧狩獵、火藥兵種、配對、存檔與觸控操作。單位升級系譜、巨型投石機展開／收起、完整陣形與官方遊戲的數值平衡也未達同等程度。模型與介面是原創實作，這些可玩規則不代表已完成整款遊戲。
